# Деплой статичного сайту на хостинг (Ukraina.com.ua) через GitHub Actions

При кожному пуші в гілку `main` або `master` GitHub Actions збирає **статичну версію сайту** (`next build` + `next export`) і по SSH завантажує вміст папки `out/` на хостинг. На хостингу сайт працює як звичайний **статичний сайт на Apache**, без запущеного Node.js.

## Що потрібно налаштувати

### 1. SSH-доступ на хостингу

- У панелі **adm.tools** (Ukraina.com.ua): **Хостинг → SSH-доступ**.
- Увімкніть SSH. Потрібні: **хост**, **логін** (наприклад `xykbi`), вхід по **ключу** (для GitHub Actions).

Якщо зараз вхід тільки по паролю — згенеруйте ключ (крок 2), додайте **публічний** ключ у панель; при потребі уточніть у підтримки, як увімкнути вхід по ключу.

### 2. SSH-ключ для GitHub Actions

На комп’ютері (один раз):

```bash
ssh-keygen -t ed25519 -C "github-actions-deploy" -f deploy_key -N ""
```

- **deploy_key** — приватний ключ (весь вміст → секрет GitHub `SSH_PRIVATE_KEY`).
- **deploy_key.pub** — публічний ключ (додати на хостинг у налаштування SSH).

### 3. Шлях до сайту на сервері (SERVER_PATH)

Це коренева папка сайту, куди Apache віддає файли (там має лежати `index.html` після деплою). Для вашого випадку це, наприклад:

**Як дізнатися в терміналі на хостингу:**

1. Підключіться по SSH або відкрийте консоль adm.tools.
2. Перейдіть у папку проєкту (де лежать `package.json` і `src/`).
3. Виконайте: `pwd` — скопіюйте результат (наприклад `/home/xykbi/top_home_shop`).

### 4. Додати публічний ключ на хостинг

У панелі **SSH-доступ** у блоці «Підключення за ключами» натисніть **Додати** і вставте вміст файлу **deploy_key.pub** (один рядок, починається з `ssh-ed25519 ...`). Збережіть. Після цього GitHub Actions зможе підключатися без пароля.

### 5. Секрети репозиторію в GitHub

У репозиторії: **Settings → Secrets and variables → Actions → New repository secret**. Додайте:

| Секрет           | Що вказати |
|------------------|------------|
| `SSH_PRIVATE_KEY` | Весь вміст файлу **приватного** ключа (`deploy_key`), включно з `-----BEGIN ... KEY-----` та `-----END ... KEY-----`. |
| `SSH_HOST`       | `xykbi.ftp.tools` (хост з панелі «Підключення по SSH»). |
| `SSH_USERNAME`   | `xykbi` (логін з панелі). |
| `SERVER_PATH`    | Повний шлях до папки сайту на сервері (результат `pwd` у папці з `package.json`, наприклад `/home/xykbi/top_home_shop`). |

Команда підключення з панелі: `ssh xykbi@xykbi.ftp.tools`.

### 6. Після деплою

- У панелі хостингу **НЕ потрібно** вмикати Node.js для цього сайту. Веб‑сервер в налаштуваннях сайту має бути **Apache** (звичайний режим).
- Після успішного workflow у папці `SERVER_PATH` з’явиться статичний сайт (HTML/CSS/JS з папки `out/`), Apache автоматично віддаватиме `index.html`.

## Перевірка

1. Запуште зміни в `main` або `master`.
2. GitHub → **Actions** → workflow **Deploy to hosting**. Якщо секрети задані й SSH працює — job завершиться успішно, на сервері оновляться файли і виконаються `npm install` та `npm run build`.

При помилці перевірте лог кроків «Check deployment secrets» та «Deploy via SSH».

## Заявки в Telegram (бот)

На сайті форма відправляється на серверний endpoint `public/api/telegram.php`, а вже він надсилає повідомлення в Telegram. Це зроблено навмисно, щоб **токен бота не потрапляв у браузер**.

### 1) Додайте змінні середовища на хостингу

У панелі хостингу (або в конфігах PHP/FastCGI) задайте:

- **`TELEGRAM_BOT_TOKEN`**: токен бота
- **`TELEGRAM_CHAT_ID`**: chat_id куди надсилати заявки (ваш особистий чат або група)

### 2) Як отримати `TELEGRAM_CHAT_ID`

- Напишіть боту (або додайте його в групу) і надішліть будь-яке повідомлення.
- Відкрийте в браузері:
  - `https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates`
- Знайдіть у відповіді `message.chat.id` — це і є `TELEGRAM_CHAT_ID`.

### 3) Важливо про безпеку

- **Не комітьте токен** в репозиторій.
- Якщо токен вже десь “засвітився” — **перевипустіть його** у BotFather і оновіть `TELEGRAM_BOT_TOKEN` на хостингу.
