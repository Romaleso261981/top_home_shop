# Деплой статичного сайту на хостинг (Ukraina.com.ua) через GitHub Actions

При кожному пуші в гілку `main` або `master` GitHub Actions збирає **статичну версію сайту** (`next build` + `next export`) і по SSH завантажує вміст папки `out/` на хостинг. На хостингу сайт працює як звичайний **статичний сайт на Apache**, без запущеного Node.js.

## Що потрібно налаштувати

### 1. SSH-доступ на хостингу

- У панелі **adm.tools** (Ukraina.com.ua): **Хостинг → SSH-доступ**.
- Увімкніть SSH. Потрібні: **хост**, **логін** (наприклад `xykbi`), вхід по **ключу** (для GitHub Actions).

Якщо зараз вхід тільки по паролю — згенеруйте ключ (крок 2), додайте **публічний** ключ у панель; при потребі уточніть у підтримки, як увімкнути вхід по ключу.

### 2. SSH-ключ для GitHub Actions

На комп’ютері (один раз):

```bash
ssh-keygen -t ed25519 -C "github-actions-deploy" -f deploy_key -N ""
```

- **deploy_key** — приватний ключ (весь вміст → секрет GitHub `SSH_PRIVATE_KEY`).
- **deploy_key.pub** — публічний ключ (додати на хостинг у налаштування SSH).

### 3. Шлях до сайту на сервері (SERVER_PATH)

Це коренева папка сайту, куди Apache віддає файли (там має лежати `index.html` після деплою). Для вашого випадку це, наприклад:

**Як дізнатися в терміналі на хостингу:**

1. Підключіться по SSH або відкрийте консоль adm.tools.
2. Перейдіть у папку проєкту (де лежать `package.json` і `src/`).
3. Виконайте: `pwd` — скопіюйте результат (наприклад `/home/xykbi/top_home_shop`).

### 4. Додати публічний ключ на хостинг

У панелі **SSH-доступ** у блоці «Підключення за ключами» натисніть **Додати** і вставте вміст файлу **deploy_key.pub** (один рядок, починається з `ssh-ed25519 ...`). Збережіть. Після цього GitHub Actions зможе підключатися без пароля.

### 5. Секрети репозиторію в GitHub

У репозиторії: **Settings → Secrets and variables → Actions → New repository secret**. Додайте:

| Секрет           | Що вказати |
|------------------|------------|
| `SSH_PRIVATE_KEY` | Весь вміст файлу **приватного** ключа (`deploy_key`), включно з `-----BEGIN ... KEY-----` та `-----END ... KEY-----`. |
| `SSH_HOST`       | `xykbi.ftp.tools` (хост з панелі «Підключення по SSH»). |
| `SSH_USERNAME`   | `xykbi` (логін з панелі). |
| `SERVER_PATH`    | Повний шлях до папки сайту на сервері (результат `pwd` у папці з `package.json`, наприклад `/home/xykbi/top_home_shop`). |

Команда підключення з панелі: `ssh xykbi@xykbi.ftp.tools`.

### 6. Після деплою

- У панелі хостингу **НЕ потрібно** вмикати Node.js для цього сайту. Веб‑сервер в налаштуваннях сайту має бути **Apache** (звичайний режим).
- Після успішного workflow у папці `SERVER_PATH` з’явиться статичний сайт (HTML/CSS/JS з папки `out/`), Apache автоматично віддаватиме `index.html`.

## Перевірка

1. Запуште зміни в `main` або `master`.
2. GitHub → **Actions** → workflow **Deploy to hosting**. Якщо секрети задані й SSH працює — job завершиться успішно, на сервері оновляться файли і виконаються `npm install` та `npm run build`.

При помилці перевірте лог кроків «Check deployment secrets» та «Deploy via SSH».

## Заявки з форми

Форма відправляє POST (JSON) на **`public/api/order.php`** (у збірці — `out/api/order.php`). Локально при `npm run dev` використовується **`/api/order`** (`src/app/api/order/route.ts`).

Порядок спрацьовування: **Bitrix24** (якщо задано URL) → **довільний вебхук** `FORM_WEBHOOK_URL` → **файл** `storage/orders.jsonl`.

### Bitrix24 — вхідний вебхук і лід

Потрібен **повний URL виклику REST-методу** `crm.lead.add` (не просто «база» вебхука без назви методу).

1. Увійдіть у свій портал Bitrix24 (хмара або коробка з типовим інтерфейсом).
2. Відкрийте розділ для розробників (назва залежить від версії інтерфейсу):
   - **Налаштування** (шестерня) → **Інтеграції** → **Вхідний вебхук** / **Вебхуки**; або
   - **Налаштування** → **Налаштування продукту** → **Розробникам** → **Інше** → **Вхідний вебхук**; або
   - у деяких тарифах: **CRM** → **Налаштування** → інструменти для розробників / вебхуки.
3. Натисніть створити **вхідний вебхук** (incoming webhook).
4. У правах доступу (scope) обов’язково увімкніть **CRM** — мінімум право на **додавання та зміну лідів** (формулювання може бути «crm» / робота з лідами). Без цього `crm.lead.add` поверне помилку доступу.
5. Після збереження портал покаже URL виду  
   `https://ВАШ_ПОРТАЛ.bitrix24.ua/rest/1/xxxxxxxxxxxxxxxx/`  
   Для сайту потрібен саме виклик методу додавання ліда. Додайте в кінець шляху **`crm.lead.add`** (без зайвих слешів):  
   `https://ВАШ_ПОРТАЛ.bitrix24.ua/rest/1/xxxxxxxxxxxxxxxx/crm.lead.add`  
   Якщо в інтерфейсі є кнопка «скопіювати виклик методу» для `crm.lead.add` — використовуйте її.
6. Цей рядок **не вставляйте в публічний git**: лише у змінні середовища на хостингу або в `.env.local` локально.

**На хостингу (Apache, `order.php`):** у панелі хостингу задайте змінну середовища  
**`BITRIX24_LEAD_WEBHOOK_URL`** = повний URL з кроку 5.  
Для сумісності також читається стара назва **`CRM_BITRIX_LEAD_WEBHOOK_URL`**.

**Локально:** у файлі `.env.local` у корені проєкту:

```bash
BITRIX24_LEAD_WEBHOOK_URL=https://ваш-портал.bitrix24.ua/rest/1/СЕКРЕТ/crm.lead.add
```

Перезапустіть `npm run dev`. Відправте тест з форми — у CRM з’явиться лід з темою «Заявка з сайту», ім’ям, телефоном, email, текстом повідомлення та посиланням на сторінку в коментарі.

Якщо Bitrix повертає помилку, перевірте: чи URL закінчується на `crm.lead.add`, чи у вебхука є право **crm**, чи не прострочений/не відкликаний вебхук.

### Довільний вебхук (не Bitrix)

Якщо **`BITRIX24_LEAD_WEBHOOK_URL`** (і **`CRM_BITRIX_LEAD_WEBHOOK_URL`**) **не задані**, використовується **`FORM_WEBHOOK_URL`** — POST з JSON-полями:

`source`, `name`, `phone`, `email`, `message`, `pageUrl`

### Файл на сервері

Якщо **немає** ні Bitrix-URL, ні `FORM_WEBHOOK_URL`, PHP дописує заявки в **`storage/orders.jsonl`** у корені сайту. Папка `storage/` має бути доступна для запису PHP.

### Локально (підсумок)

У `.env.local` достатньо **або** `BITRIX24_LEAD_WEBHOOK_URL`, **або** `FORM_WEBHOOK_URL`. Якщо жодної змінної немає, заявки пишуться в **`storage/orders.jsonl`** у проєкті.
